# 01 · Installation

中文: `docs/01-安装.md`

## Before installing

| Needed | Notes |
|---|---|
| Minecraft | 1.21.6 – 26.3, split into three variants (see the mapping table in [04-兼容与版本](04-兼容与版本.md)). Picking the wrong variant means it will not install, or `doom.ui:__load__` fails to load as a whole |
| Dependency [doom.schedule](https://github.com/Doom-Flare/doom.schedule) v2+ | This pack's alert / flash / actionbar fade-out delayed callbacks all go through it. Without it there is no error, but those effects silently do not happen |
| A save or server where you can modify `datapacks/` | Single-player save / Fabric / Paper all work (this pack is a pure datapack and does not depend on mods) |

No mods need to be installed, and no tooling beyond Java is needed.

## Single-player save (30 seconds)

1. Download the zip for your variant per the mapping table (1.21.9–1.21.10 → `doom.ui-v2.1.0.zip`; 1.21.11+ → `...-mc1.21.11+.zip`; 1.21.6–1.21.8 → `...-mc1.21.6-1.21.8.zip`). Unzip to get the `doom.ui/` folder.
2. Obtain the `doom.schedule/` folder the same way.
3. Put both folders in whole:
   ```
   <your save>/datapacks/
   ```
   Note that what goes in is the folder (`datapacks/doom.ui/pack.mcmeta` at this level must be right), not the zip, and do not nest an extra level.
4. Enter the world and type `/reload`.
5. Verify:
   ```
   /function doom.ui:api/actionbar {with:{targets:"@a",content:[{"text":"Hello","color":"gold"}],time:200}}
   ```
   A gold `Hello` appearing on screen for 10 seconds = it is installed.

## Server (`world/datapacks/`)

The same as single-player, except the directory becomes, under the server root:

```
<server>/world/datapacks/doom.ui/
<server>/world/datapacks/doom.schedule/
```

After placing them, `/reload` from the console or in game. On a multiplayer server the player selector (`targets:"@a"`) can be whichever you like.
This pack creates sessions per player, so they do not bleed into each other.

> Multiple worlds / dimensions: `datapacks/` takes effect per save (world). If you want it in every world, put a copy in each world's `datapacks/`.

## How to confirm it is really running after installing

| Check | How to look |
|---|---|
| No load errors | Search `doom.ui` in `logs/latest.log`; a `Failed to load function` means it is not installed properly (usually a missing dependency or the wrong directory level) |
| Is the dependency there | If `/function doom.schedule:...` autocompletes, the dependency is there too |
| Did the effect appear | Type the actionbar example above; if nothing happens, check in the order ① dependency ② log ③ `/reload` |

## Uninstalling

Delete `datapacks/doom.ui/` (keep `doom.schedule/` if something else still needs it) → `/reload`.

This pack does not touch vanilla gamerules (it does not change gamerules, does not touch mob spawning, does not write world files), so the world returns to its original state after uninstalling.
The only residue is one scoreboard score per player (`dt.uid`), bounded and harmless; the cause is in F-8 of the [CHANGELOG](../CHANGELOG.md).

## Common "will not install"

| Symptom | Cause |
|---|---|
| The pack is not visible in game | There is an extra level inside `datapacks/` (ending up as `datapacks/doom.ui/doom.ui/`), or the zip was put in without unzipping |
| It reports a version mismatch | The wrong variant was picked; compare with the mapping table in [04-兼容与版本](04-兼容与版本.md) |
| `/function doom.ui:api/actionbar` does not autocomplete | No `/reload`, or the pack was not recognized (check the log first) |
| Only alert / flash / fade-out do nothing, everything else is fine | `doom.schedule` v2+ is missing |
