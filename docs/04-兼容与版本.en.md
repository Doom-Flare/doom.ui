# 04 · Compatibility and versions

中文: `docs/04-兼容与版本.md`

## Version matrix (MC version → which variant to use)

This pack has two version dividing lines, so it is split into three variants:

| MC version | data format | Which variant | `gamerule` name | Measured |
|---|---|---|---|---|
| 1.21.6 / 1.21.7 / 1.21.8 | 80 / 81 | `v2.1.0-mc1.21.6-1.21.8` | old `maxCommandChainLength` | 🟡 source pack mcmeta as-is |
| 1.21.9 / 1.21.10 | 88.0 | `v2.1.0` ★ (mcmeta declares `[88,0]`–`88`) | old | ✅ 53 cases / 335 assertions · self-assertions 15/15 |
| 1.21.11 / 26.1 / 26.1.1 / 26.1.2 / 26.2 / 26.3 | 94.1 – 121.0 | `v2.1.0-mc1.21.11+` (mcmeta declares `[94,1]`–`121`) | new `max_command_sequence_length` | ✅ 15/15 (26.3) |
| 1.21.5 and lower | ≤ 71 | ❌ Not supported | — | — |

The two dividing lines are:

1. 1.21.9: `pack.mcmeta` mandates `min_format`/`max_format`. Missing them rejects the whole pack:
   `Pack declares support for version newer than 81, but is missing mandatory fields min_format and max_format`.
   And `min_format` must == `supported_formats.min_inclusive`, `max_format` must == `supported_formats.max_inclusive`
   (a mismatch ⇒ `Pack version declaration mismatch ...`).
2. 1.21.11: `gamerule maxCommandChainLength` is renamed `max_command_sequence_length`.
   The old name is a parse-time error on the new version ⇒ `doom.ui:__load__` fails to load as a whole ⇒ the `#minecraft:load` tag loses its reference
   ⇒ the pack does not run at all:
   `Failed to load function doom.ui:__load__ ... Whilst parsing command on line 45: Incorrect argument for command`.

> Why one pack cannot cover everything: `gamerule` is decided at parse time, and the old and new names cannot both be legal ✗ ⇒ splitting is the only option ✓.
> `modern-1.21.11+`'s mcmeta declares 48–121, and its `pack_format 81` covers 1.21.6–1.21.10,
> but those versions need the old gamerule name ⇒ in practice it cannot be used across them.

| Other | Works? |
|---|---|
| Single-player save / server (Fabric / Paper / vanilla server) | ✅ both work | For a server put them in `world/datapacks/` |
| Bedrock | ❌ | This pack is a Java Edition datapack |

## Where the variants live in the repo

- The primary one (`v2.1.0`, 1.21.9–1.21.10): repo root [`doom.ui/`](../doom.ui), packed into `dist/doom.ui-v2.1.0.zip`.
- The other two: [`variants/doom.ui-1.21.11-26.3/`](../variants/doom.ui-1.21.11-26.3) and [`variants/doom.ui-1.21.6-1.21.8/`](../variants/doom.ui-1.21.6-1.21.8),
  packed into `dist/doom.ui-v2.1.0-mc1.21.11+.zip` and `dist/doom.ui-v2.1.0-mc1.21.6-1.21.8.zip` respectively.
- Pack all three at once: `node src/tools/make_dist.mjs` (`--check` proves byte-for-byte consistency).

> Self-declared range == actual capability (M6): the two modern variants now use purely new-style mcmeta (keeping only `min_format`/`max_format`).
> Per rule 4, a declared range reaching 82+ forbids `supported_formats`. After the change there are 0 deprecation warnings on 1.21.11+,
> and the range no longer "claims up to 26.3 while only running on 1.21.10". Re-run on a real 26.3 machine: 15/15 ✓.

Between the three, only `pack.mcmeta` and 1 `gamerule` line of `__load__.mcfunction` differ,
and the other 140 files are byte-for-byte identical ⇒ the public API is unchanged down to the character ✓.

## Dependencies

| Dependency | Version | What happens without it |
|---|---|---|
| [doom.schedule](https://github.com/DoomDecapitator/doom.schedule) | v2.3+ (also picked by MC version) | No error, but the delayed callbacks of alert / flash / actionbar fade-out silently do not happen — this is the most common "installed but nothing happens" |

This pack does not conflict with `doom.nats` or `doom.log`, and they can be installed together (different namespaces).

## How to read the version number

- `v2.1.0` splits into `MAJOR.MINOR.PATCH`. Multi-version support is a MINOR (a backward-compatible new capability; the API is unchanged).
- Asset names and tags both carry the full version number (such as `doom.ui-v2.1.0.zip` / tag `v2.1.0`); **do not use old files without a version number**.
- The earlier `v2.0-beta` was a pre-release; v2.1.0 supersedes it, and the only change is multi-version adaptation — the gameplay behaviour is the same.
## Upgrading / downgrading

1. Stop the server (or exit the world in single-player).
2. Delete the old `datapacks/doom.ui/` and put in the new `doom.ui/`.
3. `/reload`.

The pack writes no world data files, so replacing the folder is enough; the two storages `doom.ui:ctx` / `doom.ui:mixer` survive `/reload`,
so to clear them completely use `/function doom.ui:__unload__` (or `silent_clear_all` before swapping the pack).

> **Back up your save** before upgrading across major versions. During Beta the data structures (the field names in storage) are not promised to be backward compatible.

## Uninstalling

Delete `datapacks/doom.ui/` → `/reload`. This pack sets `gamerule max_command_sequence_length 2147483647` only once, in `__load__` (to prevent command chain truncation), and does not touch mob spawning; the world returns to its original state after uninstalling.
The only residue: one `dt.uid` scoreboard score per player, bounded and harmless. The cause is in F-8 of the [CHANGELOG](../CHANGELOG.md).

## Performance boundaries (when to use less of it)

Concurrency ladder measured on an idle machine (30 UI slots per player running at once):

| Players online at once | Full-load TPS | Command chain truncations | Correctness |
|---|---|---|---|
| 10 | 19.96 | 0 | all green |
| 20 | 19.99 | 0 | all green |
| 30 | 20.25 | 0 | all green |
| 40 | ≈12.4 – 13.9 | 0 | all green |
| 60 | ≈8.9 | 0 | all green |

The knee is between 20 and 40 players, and the bottleneck is countdown (at 40 players the TPS delta is −7.51, versus actionbar −0.58, bossbar −1.01, xpbar ≈0).
Above forty players, using fewer long countdowns and more one-shot actionbars is recommended. For where the numbers come from and the reproduction scope, see the [CHANGELOG](../CHANGELOG.md).
