# 04 · 兼容与版本

## 版本矩阵（MC 版本 → 用哪份变体）

本包有两条版本分界线，所以拆成三份变体：

| MC 版本 | data format | 用哪份变体 | `gamerule` 名 | 实测 |
|---|---|---|---|---|
| 1.21.6 / 1.21.7 / 1.21.8 | 80 / 81 | `v2.1.0-mc1.21.6-1.21.8` | 旧 `maxCommandChainLength` | 🟡 源包 mcmeta 原样 |
| 1.21.9 / 1.21.10 | 88.0 | `v2.1.0` ★（mcmeta 声明 `[88,0]`–`88`） | 旧 | ✅ 53 用例 / 335 断言 · 自断言 15/15 |
| 1.21.11 / 26.1 / 26.1.1 / 26.1.2 / 26.2 / 26.3 | 94.1 – 121.0 | `v2.1.0-mc1.21.11+`（mcmeta 声明 `[94,1]`–`121`） | 新 `max_command_sequence_length` | ✅ 15/15（26.3） |
| 1.21.5 及更低 | ≤ 71 | ❌ 不支持 | — | — |

两条分界线分别是：

1. 1.21.9：`pack.mcmeta` 强制要求 `min_format`/`max_format`。缺了会整包拒收：
   `Pack declares support for version newer than 81, but is missing mandatory fields min_format and max_format`。
   且 `min_format` 必须 == `supported_formats.min_inclusive`、`max_format` 必须 == `supported_formats.max_inclusive`
   （不一致 ⇒ `Pack version declaration mismatch ...`）。
2. 1.21.11：`gamerule maxCommandChainLength` 改名 `max_command_sequence_length`。
   旧名在新版上是解析期错误 ⇒ `doom.ui:__load__` 整支加载失败 ⇒ `#minecraft:load` 标签失去引用
   ⇒ 包根本没跑起来：
   `Failed to load function doom.ui:__load__ ... Whilst parsing command on line 45: Incorrect argument for command`。

> 为什么不能“一份通吃”：`gamerule` 是解析期判定的，新旧名不可能同时合法 ✗ ⇒ 只能拆包 ✓。
> `modern-1.21.11+` 的 mcmeta 声明 48–121，它的 `pack_format 81` 覆盖 1.21.6–1.21.10，
> 但那些版本要旧 gamerule 名 ⇒ 实际不可跨用。

| 其他 | 能不能用 |
|---|---|
| 单人存档 / 服务器（Fabric / Paper / 原版服务端） | ✅ 都行 | 服务器放 `world/datapacks/` |
| Bedrock（基岩版） | ❌ | 本包是 Java 版数据包 |

## 变体在仓库里放哪

- 主用份（`v2.1.0`，1.21.9–1.21.10）：仓库根 [`doom.ui/`](../doom.ui)，打包成 `dist/doom.ui-v2.1.0.zip`。
- 另两份：[`variants/doom.ui-1.21.11-26.3/`](../variants/doom.ui-1.21.11-26.3) 与 [`variants/doom.ui-1.21.6-1.21.8/`](../variants/doom.ui-1.21.6-1.21.8)，
  分别打包成 `dist/doom.ui-v2.1.0-mc1.21.11+.zip` 与 `dist/doom.ui-v2.1.0-mc1.21.6-1.21.8.zip`。
- 三份一次打包：`node src/tools/make_dist.mjs`（`--check` 逐字节自证）。

> 自称区间 == 实际能力（M6）：两份 modern 变体改用纯新式 mcmeta（只留 `min_format`/`max_format`）。
> 按规则 4，声明范围触及 82+ 就禁止 `supported_formats`。改后 1.21.11+ 上 0 条 deprecation 告警，
> 区间不再“自称到 26.3 却只能在 1.21.10 跑”。已在 26.3 真机复跑 15/15 ✓。

三份之间只有 `pack.mcmeta` 与 `__load__.mcfunction` 的 1 行 `gamerule` 不同，
其余 140 个文件逐字节相同 ⇒ 对外 API 一字未改 ✓。

## 依赖

| 依赖 | 版本 | 缺了会怎样 |
|---|---|---|
| [doom.schedule](https://github.com/DoomDecapitator/doom.schedule) | v2.3+（同样按 MC 版本选变体） | 不报错，但 alert / flash / actionbar 淡出的延迟回调静默不发生，这是最常见的“装了没反应” |

本包与 `doom.nats`、`doom.log` 互不冲突，可以同时装（不同命名空间）。

## 版本号怎么读

- `v2.1.0` 分 `MAJOR.MINOR.PATCH` 三段。多版本支持属 MINOR（向后兼容的新能力，未改 API）。
- 附件名与 tag 都带完整版本号（如 `doom.ui-v2.1.0.zip` / tag `v2.1.0`），**别用不带版本号的旧文件**。
- 更早的 `v2.0-beta` 是预发布，v2.1.0 已取代它；改动只有多版本适配，玩法行为一致。
## 升级 / 降级

1. 停服（或单人退出世界）。
2. 删掉旧的 `datapacks/doom.ui/`，放进新的 `doom.ui/`。
3. `/reload`。

包内不写世界数据文件，替换文件夹即可；`doom.ui:ctx` / `doom.ui:mixer` 两个 storage 会跨 `/reload` 保留，
想彻底清干净用 `/function doom.ui:__unload__`（或在换包前 `silent_clear_all`）。

> 跨大版本升级前**备份存档**。Beta 期间数据结构（storage 的字段名）不承诺向下兼容。

## 卸载

删掉 `datapacks/doom.ui/` → `/reload`。本包只在 `__load__` 里设一次 `gamerule max_command_sequence_length 2147483647`（防命令链截断），不动刷怪；卸载后世界回到原样。
唯一残留：每个玩家一条 `dt.uid` 计分板分数，有界无害。成因见 [CHANGELOG](../CHANGELOG.md) 的 F-8。

## 性能边界（什么时候该少用）

空载机上实测的并发阶梯（每人 30 个 UI 槽一起跑）：

| 同时在服人数 | 满载 TPS | 命令链截断 | 正确性 |
|---|---|---|---|
| 10 | 19.96 | 0 | 全绿 |
| 20 | 19.99 | 0 | 全绿 |
| 30 | 20.25 | 0 | 全绿 |
| 40 | ≈12.4 – 13.9 | 0 | 全绿 |
| 60 | ≈8.9 | 0 | 全绿 |

拐点在 20–40 人之间，瓶颈是 countdown（40 人时 TPS 增量 −7.51，actionbar −0.58、bossbar −1.01、xpbar ≈0）。
四十人以上建议少用长倒计时、多用一次性 actionbar。数字出处与复现口径见 [CHANGELOG](../CHANGELOG.md)。
